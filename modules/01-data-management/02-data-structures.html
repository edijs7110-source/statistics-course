Data structures in R

Vectors, lists, matrices, arrays and data frames: choosing the right container

Work with attributes, lists, matrices, arrays, data frames and tibbles, convert between them, and choose the right structure for the data in front of you.

Module 1 · Lesson 2 of 14 Week 17 of 160 About 5–7 hours

Every piece of data in R lives in a container, and choosing the right one makes everything else easier. A set of temperature readings is a vector. A batch record, with its ID, its times, its readings and its lab results all bundled together, is a list. A grid of thermocouple readings is a matrix, readings by reactor, hour and day form an array, and a table of batches is a data frame. This lesson is a tour of all five, and how to move data between them.

Think of these as lab containers: a vector is a row of test tubes, a list is a sample box with labeled compartments for anything, and a data frame is a well-organized rack where every row is one sample.

In this lesson you’ll:

  • attach names and other attributes to vectors
  • build lists, and get things out of them with [[ ]] and $
  • work with matrices and arrays, and summarize them by row, column or layer
  • see what makes a data frame, and how tibbles differ
  • convert between structures, and split data into groups

Vectors and attributes

You know vectors from Module 0: an ordered set of values, all of the same type. typeof() tells you how R stores them:

typeof(c(178.2, 181.5))   # decimal numbers
#> [1] "double"
typeof(c(3L, 5L))         # whole numbers: the L makes an integer
#> [1] "integer"
typeof("B18")
#> [1] "character"
typeof(TRUE)
#> [1] "logical"

Vectors can carry attributes: extra information attached to them. The one you’ll use most is names:

setpoints <- c(R1 = 180, R2 = 175)
setpoints
#>  R1  R2 
#> 180 175
names(setpoints)
#> [1] "R1" "R2"
setpoints["R2"]
#>  R2 
#> 175

You can attach any attribute you like. Here’s a handy one for engineers, the units:

temps <- c(178.2, 181.5, 179.8)
attr(temps, "units") <- "°C"
attributes(temps)
#> $units
#> [1] "°C"
mean(temps)
#> [1] 179.8333

Attributes ride along with the data, but most functions ignore them: mean() doesn’t care about the units. Factors (Module 0, Lesson 2) are built the same way: integer codes, plus a levels attribute.

Your turn. Build a named vector pressure holding the pressures R1 = 5.1 and R2 = 4.7 bar, then pick out R2’s.

Write the names inside c(), like this: c(R1 = 5.1, ...).

pressure <- c(R1 = 5.1, R2 = 4.7)
pressure["R2"]

Lists: containers for anything

A vector holds one type. A list can hold anything: numbers, text, vectors of different lengths, data frames, even other lists. That makes it perfect for a record that bundles different kinds of information. Here’s batch B18, which ran on reactor R2 on the morning of 10 March:

b18 <- list(
  batch_id = "B18",
  reactor = "R2",
  operator = "Jonas",
  temps_C = c(28.5, 84.9, 139.3, 166.3, 166.8, 165.8),
  lab = list(purity_pct = 98.96, water_ppm = 410, color_apha = 5)
)
str(b18)
#> List of 5
#>  $ batch_id: chr "B18"
#>  $ reactor : chr "R2"
#>  $ operator: chr "Jonas"
#>  $ temps_C : num [1:6] 28.5 84.9 139.3 166.3 166.8 ...
#>  $ lab     :List of 3
#>   ..$ purity_pct: num 99
#>   ..$ water_ppm : num 410
#>   ..$ color_apha: num 5

str() shows the structure: five elements, the last one a list of its own. There are three ways to get things out, and the difference matters:

b18$operator          # $ by name: the element itself
#> [1] "Jonas"
b18[["temps_C"]]      # [[ ]]: also the element itself
#> [1]  28.5  84.9 139.3 166.3 166.8 165.8
b18["temps_C"]        # [ ]: a smaller LIST containing the element
#> $temps_C
#> [1]  28.5  84.9 139.3 166.3 166.8 165.8
b18$lab$water_ppm     # dig into a list inside a list
#> [1] 410

The rule: [[ ]] and $ take something out of the list; [ ] gives you back a list. If you think of a list as a box of labeled compartments, x["a"] hands you a smaller box holding compartment a, and x[["a"]] hands you what’s inside it.

You add or change elements just like with data frames:

b18$on_spec <- b18$lab$purity_pct >= 98.5
names(b18)
#> [1] "batch_id" "reactor"  "operator" "temps_C"  "lab"      "on_spec"

B18’s water content is 410 ppm, about twice the usual. Remember that number: you’ll find out why in Lesson 5, when you link the batches to their raw-material suppliers.

Your turn. Get B18’s color result, as a number, out of the nested lab list.

Chain two $s: first into lab, then to color_apha.

b18 <- list(
  batch_id = "B18",
  reactor = "R2",
  temps_C = c(28.5, 84.9, 139.3, 166.3, 166.8, 165.8),
  lab = list(purity_pct = 98.96, water_ppm = 410, color_apha = 5)
)
b18$lab$color_apha

b18[["lab"]][["color_apha"]] works too.

Matrices: grids of numbers

A matrix is a vector arranged in rows and columns, with one type throughout. Here are temperatures measured at four positions along a tubular reactor, in three runs:

profile <- matrix(c(150, 172, 181, 176,
                    148, 170, 183, 179,
                    152, 175, 184, 178), nrow = 3, byrow = TRUE,
                  dimnames = list(c("run1", "run2", "run3"), c("z0.5m", "z1.0m", "z1.5m", "z2.0m")))
profile
#>      z0.5m z1.0m z1.5m z2.0m
#> run1   150   172   181   176
#> run2   148   170   183   179
#> run3   152   175   184   178
dim(profile)
#> [1] 3 4
profile["run2", "z1.5m"]
#> [1] 183

rowMeans() and colMeans() summarize each row or column. For any other function, apply() does the job: its second argument is the margin, 1 for rows and 2 for columns:

colMeans(profile)              # the average temperature at each position
#>    z0.5m    z1.0m    z1.5m    z2.0m 
#> 150.0000 172.3333 182.6667 177.6667
apply(profile, 1, max)         # the hottest reading in each run
#> run1 run2 run3 
#>  181  183  184

The column means show the classic hot spot of a tubular reactor: the temperature peaks about 1.5 m along the tube, where the reaction runs fastest, then falls as the reactants are used up.

Your turn. Use apply() and which.max() to find the position of the hottest reading in each run.

You want to apply which.max to each row, so the margin is 1.

profile <- matrix(c(150, 172, 181, 176,
                    148, 170, 183, 179,
                    152, 175, 184, 178), nrow = 3, byrow = TRUE,
                  dimnames = list(c("run1", "run2", "run3"), c("z0.5m", "z1.0m", "z1.5m", "z2.0m")))
apply(profile, 1, which.max)

Position 3, the 1.5 m thermocouple, in every run.

Arrays: more than two dimensions

An array is a matrix with more dimensions. Here are average temperatures for two reactors, at four times of day, over three days: a 2 × 4 × 3 array.

temps <- array(
  c(175, 172, 177, 174, 179, 176, 176, 173,
    176, 173, 178, 175, 180, 177, 177, 174,
    174, 171, 176, 173, 178, 175, 175, 172),
  dim = c(2, 4, 3),
  dimnames = list(reactor = c("R1", "R2"), hour = c("06", "12", "18", "24"), day = c("Mon", "Tue", "Wed"))
)
temps[, , "Mon"]          # one day: a 2 x 4 matrix
#>        hour
#> reactor  06  12  18  24
#>      R1 175 177 179 176
#>      R2 172 174 176 173
temps["R1", "12", ]       # R1 at noon, every day
#> Mon Tue Wed 
#> 177 178 176

Indexing works just like a matrix, with one position per dimension, and a blank means “all”. apply() works too: a margin of c(1, 3) means “keep reactors and days, and summarize over hours”.

Your turn. Pull out reactor R2’s four readings on Tuesday.

Three positions: the reactor, then the hours (blank for all of them), then the day: temps["R2", , "Tue"].

temps <- array(
  c(175, 172, 177, 174, 179, 176, 176, 173,
    176, 173, 178, 175, 180, 177, 177, 174,
    174, 171, 176, 173, 178, 175, 175, 172),
  dim = c(2, 4, 3),
  dimnames = list(reactor = c("R1", "R2"), hour = c("06", "12", "18", "24"), day = c("Mon", "Tue", "Wed"))
)
temps["R2", , "Tue"]

Data frames and tibbles

A data frame is the structure you know best, and now you can see what it really is: a list of vectors of the same length, one per column, with a names attribute and a class attribute saying “treat me as a table”.

batches <- read.csv("data/batches.csv")
typeof(batches)
#> [1] "list"
class(batches)
#> [1] "data.frame"
length(batches)       # the number of columns, because it's a list of columns
#> [1] 12

A tibble is the tidyverse’s version. It’s still a data frame, so everything works the same, but it prints more helpfully and it’s a little stricter. One example: a data frame lets $ match part of a column name, which can quietly hand you the wrong column. A tibble refuses:

df <- data.frame(batch_id = c("B01", "B02"), yield_pct = c(70.2, 53.7))
df$yie                      # data frame: partial match, returns yield_pct!
#> [1] 70.2 53.7
tb <- dplyr::as_tibble(df)
tb$yie                      # tibble: NULL, with a warning
#> Warning: Unknown or uninitialised column: `yie`.
#> NULL

A tibble’s column can even hold a list, called a list-column, which is handy when each row has a small table of its own, like the chromatograph peaks in Lesson 9.

Your turn. Build a tibble with a column reactor holding "R1" and "R2", and a column setpoint_C holding 180 and 175.

tibble() works like data.frame(): name = values, separated by commas.

Moving between structures

Real work keeps converting from one structure to another. The most useful conversions:

From To How
A list of vectors One vector unlist(x)
A matrix A data frame as.data.frame(m)
A data frame of numbers A matrix as.matrix(df)
A data frame A list of data frames, one per group split(df, df$group)
A list of data frames One data frame dplyr::bind_rows(x) or do.call(rbind, x)

split() is particularly useful: it breaks data into groups, so you can work on each group with lapply() or sapply(). Here are the lab results, split by analyte:

lab <- read.csv("data/lab_results.csv")
by_analyte <- split(lab$value, lab$analyte)
str(by_analyte)
#> List of 3
#>  $ color : num [1:40] 13 21 15 21 14 11 32 17 21 22 ...
#>  $ purity: num [1:46] 98.7 98.9 99.6 98.8 98.9 ...
#>  $ water : num [1:38] 154 184 221 219 174 221 195 217 154 238 ...
sapply(by_analyte, length)
#>  color purity  water 
#>     40     46     38

That’s exactly what tapply() did for you in Module 0, done in two steps you can see.

Your turn. Split the lab values by analyte, and compute the median of each group with sapply().

split(values, groups): the values are lab$value, and the groups are lab$analyte.

lab <- read.csv("data/lab_results.csv")
by_analyte <- split(lab$value, lab$analyte)
sapply(by_analyte, median)

Choosing the right structure

You have… Use a…
Many values of one kind, like a column of readings Vector
A record that mixes kinds of information List
A grid of numbers, like a temperature profile or a matrix for algebra Matrix
Numbers organized by three or more factors Array (or a long data frame, Lesson 3)
A table of observations and variables Data frame or tibble
A table where each row has its own little table Tibble with a list-column

Most of the time it’s a data frame. The others are the tools you reach for along the way.

Challenge round

Challenge 1 · Glue the runs together. Three runs were logged as separate data frames. Combine them into one data frame with 9 rows, and a column run saying which run each row came from.

bind_rows() takes the list, and its .id argument names a new column that records which list element each row came from: bind_rows(runs, .id = "run").

library(dplyr)
runs <- list(
  run1 = data.frame(position_m = c(0.5, 1.0, 1.5), temp_C = c(150, 172, 181)),
  run2 = data.frame(position_m = c(0.5, 1.0, 1.5), temp_C = c(148, 170, 183)),
  run3 = data.frame(position_m = c(0.5, 1.0, 1.5), temp_C = c(152, 175, 184))
)
bind_rows(runs, .id = "run")

Challenge 2 · Daily means from an array. Using the temps array, compute the mean temperature for each reactor on each day: a 2 × 3 table, with reactors in rows and days in columns.

The margin lists the dimensions you want to keep: reactors (dimension 1) and days (dimension 3). In R, that’s c(1, 3).

temps <- array(
  c(175, 172, 177, 174, 179, 176, 176, 173,
    176, 173, 178, 175, 180, 177, 177, 174,
    174, 171, 176, 173, 178, 175, 175, 172),
  dim = c(2, 4, 3),
  dimnames = list(reactor = c("R1", "R2"), hour = c("06", "12", "18", "24"), day = c("Mon", "Tue", "Wed"))
)
apply(temps, c(1, 3), mean)

R1 runs 3 °C hotter than R2 every day, and both were warmest on Tuesday.

Quick quiz

1. What’s the main difference between a vector and a list?

Vectors are for many values of one kind. Lists are for records that mix different kinds of things.

2. x <- list(a = 1:3, b = "hi"). What does x["a"] return?

Single brackets return a smaller list. To get the vector itself, use x[["a"]] or x$a.

3. What does apply(m, 2, mean) compute for a matrix m?

The margin 1 means rows and 2 means columns, so this is the same as colMeans(m).

4. What is a data frame, underneath?

That’s why length() of a data frame counts its columns, and why columns can have different types.

5. df is a data frame with a column yield_pct. What does df$yie return?

Data frames quietly match partial names, which can return the wrong column. Tibbles refuse, which is safer.

6. You have a list of 20 data frames, one per batch, all with the same columns. How do you make one data frame?

bind_rows() stacks data frames on top of each other. split() goes the other way.

Wrap-up

You can now pick the right container for any data. Here’s what you’ve learned:

  • Vectors hold one type, and can carry attributes like names and units.
  • Lists hold anything. [[ ]] and $ take an element out; [ ] returns a smaller list.
  • Matrices and arrays are grids with two or more dimensions. Summarize them with rowMeans(), colMeans() and apply().
  • Data frames are lists of equal-length columns. Tibbles print better and are stricter.
  • Converting is everyday work: unlist(), as.data.frame(), as.matrix(), split() and bind_rows().

NoteKey words from this lesson
Attribute
Extra information attached to an object, such as names, dim, class or your own units.
List
A container that can hold objects of any type and length, including other lists.
[[ ]] and $
Extract a single element from a list. [ ] returns a smaller list instead.
Matrix
A two-dimensional grid of values of one type.
Array
A grid of values with any number of dimensions.
Margin
In apply(), the dimensions to keep: 1 for rows, 2 for columns, and so on.
Tibble
The tidyverse’s data frame: it prints compactly and never does partial matching.
List-column
A data frame column whose cells are lists, such as one small table per row.
