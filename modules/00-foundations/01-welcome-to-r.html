Welcome to R

Your first conversation with R

Use R as a calculator, store values in objects, call functions, and make sense of error messages.

Module 0 · Lesson 1 of 14 Week 1 of 160 About 5–7 hours

Hi, and welcome! Chemists have the lab notebook, engineers have the spreadsheet, and statisticians have R: a free programming language built specifically for working with data. Today you’ll write your first lines of it. By the end of this lesson, R will be your calculator, your unit converter and your memory for numbers. It never makes an arithmetic slip, and it never forgets a value.

Hi, I’m Fizz! I’ll pop up with tips along the way. Whenever you see a dark box with a Run Code button, that’s real R running right here in your browser. Go ahead and experiment. You can’t break anything, I promise.

In this lesson you’ll:

  • run your first R code
  • use R as a calculator, from unit conversions to the ideal gas law
  • give values names so you can reuse them
  • use built-in functions like round() and log10()
  • read error messages without panicking

Your first line of R

Let’s start with the simplest possible conversation. Press Run Code in the box below. (The very first run on a page takes a few seconds while R loads. After that it’s instant.)

R read your line, worked it out, and answered [1] 2. The [1] just means “here’s the first value of the answer”. It’ll make more sense in the next lesson, so you can ignore it for now.

Now change the numbers and run it again. Try 40 + 2, or 273 * 2. This is how you’ll learn R: change something, run it, see what happens.

You’ll also see examples like this one, where I’ve already run the code for you. Lines starting with #> show what R printed:

10 - 3
#> [1] 7

Little tip: type the examples into a live box instead of copying them. Your fingers learn R faster than your eyes do. And guess the answer before you press Run!

R as a calculator

R knows all the usual arithmetic, plus a couple of extras:

You type It means Example Answer
+ - add, subtract 25 + 273.15 298.15
* / multiply, divide 7 / 2 3.5
^ to the power of 2^10 1024
%% remainder 17 %% 5 2

Here’s one you’ll use all the time in chemistry. To turn a temperature in °C into kelvin, you add 273.15:

25 + 273.15
#> [1] 298.15

So room temperature, 25 °C, is 298.15 K.

R follows the order of operations you know from school: powers first, then multiplication and division, then addition and subtraction. Parentheses beat everything. Compare these:

2 + 3 * 4
#> [1] 14
(2 + 3) * 4
#> [1] 20

When in doubt, add parentheses. They’re free, and they make your intent obvious to anyone reading your code, including future you.

Really big and really tiny numbers

Science is full of numbers that are awkward to type. R uses scientific notation: 6.022e23 means 6.022 \times 10^{23} (Avogadro’s number), and 1.6e-19 means 1.6 \times 10^{-19} (the charge of an electron, in coulombs).

6.022e23 * 2      # molecules in two moles
#> [1] 1.2044e+24

Your first engineering calculation

Here’s the ideal gas law, PV = nRT, rearranged for the number of moles, n = \dfrac{PV}{RT}. Let’s find out how many moles of gas fill 0.0224 m³ at 1 atm (101,325 Pa) and 0 °C (273.15 K), with R = 8.314 J/(mol·K):

(101325 * 0.0224) / (8.314 * 273.15)
#> [1] 0.9994324

About one mole. That’s the famous “22.4 liters per mole” you may remember from chemistry class, and R just worked it out for you.

Your turn. A reactor runs at 350 °C. What’s that in kelvin?

Add 273.15 to the temperature in °C.

350 + 273.15

One more. A reactor heats up from 20 °C to 80 °C in 15 minutes. What’s the average heating rate, in °C per minute?

The rate is the temperature change divided by the time. Make sure R subtracts before it divides, so put the subtraction in parentheses.

(80 - 20) / 15

Without the parentheses, 80 - 20 / 15 would divide first and give about 78.7, which is nonsense as a heating rate.

NoteGo deeper: why 0.1 + 0.2 isn’t exactly 0.3

Computers store numbers in binary, and most decimal fractions, like 0.1, can’t be written exactly in binary, just as 1/3 can’t be written exactly in decimal. The errors are tiny, but they show up if you test whether two numbers are exactly equal (== asks “are these equal?”):

0.1 + 0.2 == 0.3
#> [1] FALSE
isTRUE(all.equal(0.1 + 0.2, 0.3))
#> [1] TRUE

all.equal() allows for those tiny rounding differences, so use it to compare decimals. Module 4 explains how computers handle numbers.

Giving values names

Typing 273.15 or 8.314 again and again gets old fast. So let’s give values names. In R you store a value in an object with the arrow <-:

reactor_temp <- 350

Read it as “reactor_temp gets 350”. Nothing is printed, because you only stored the value. Type the name to see it, or use it in a calculation:

reactor_temp
#> [1] 350
reactor_temp + 273.15
#> [1] 623.15

Now change temp_K to 298.15 (room temperature) and run it again. One edit, and everything that depends on it updates. In a real analysis with hundreds of steps, this is a superpower: it makes your work reproducible, because anyone can rerun it and get exactly the same answer.

A few naming rules: names can use letters, numbers, _ and ., but must start with a letter. No spaces! Capitals matter, so Temp and temp are different objects. And avoid naming things T or F, because R uses those as shortcuts for TRUE and FALSE.

A good style is to join words with underscores and include units in the name, like flow_rate_Lmin or mass_kg. In RStudio, Alt + - types the arrow for you (Option + - on a Mac).

Your turn. A storage tank holds 2.5 m³ of water, and water’s density is 997 kg/m³. Compute the mass of the water (mass = density × volume).

Multiply the two objects: density_kgm3 * volume_m3.

density_kgm3 <- 997
volume_m3 <- 2.5
mass_kg <- density_kgm3 * volume_m3
mass_kg

Functions: R’s toolbox

R comes with thousands of built-in functions: little machines that take inputs and give back an answer. You call a function by writing its name followed by parentheses with the inputs, called arguments, inside:

sqrt(16)          # square root
#> [1] 4
abs(-3)           # absolute value
#> [1] 3
round(3.14159, digits = 2)
#> [1] 3.14

Look at round(): the first argument is the number, and digits says how many decimal places to keep. If you leave digits out, R uses its default, which is 0:

round(3.14159)
#> [1] 3

Logs, the chemist’s favorite

You’ll meet logarithms all the time: in pH, in reaction rates, in decibels. R has a few:

log10(1000)    # base 10: 10^3 = 1000
#> [1] 3
log(100)       # careful: plain log() is the natural log, base e
#> [1] 4.60517
exp(1)         # e itself
#> [1] 2.718282

So the pH of a solution, \text{pH} = -\log_{10}[\text{H}^+], is one line. Pure water has [\text{H}^+] = 10^{-7} mol/L:

-log10(1e-7)
#> [1] 7

pH 7, neutral, just as it should be.

Functions inside functions

You can put one function inside another, and R works from the inside out:

round(sqrt(2), digits = 3)
#> [1] 1.414

First sqrt(2) gives 1.41421…, then round() keeps three decimals.

Your first statistics

The function c() (for combine) bundles several values together. Say you ran the same titration five times and got these volumes, in mL:

titrations <- c(24.8, 25.1, 24.9, 25.3, 25.0)
mean(titrations)
#> [1] 25.02
median(titrations)
#> [1] 25

The mean is the average: add them all up and divide by how many there are. The median is the middle value once they’re sorted. You’ll use both constantly, and Lesson 7 is all about them.

Your turn. A solution has a hydrogen-ion concentration of 3.2 \times 10^{-4} mol/L. What’s its pH, rounded to two decimals?

Inside out: -log10(3.2e-4) gives the pH, then wrap it in round(..., digits = 2).

round(-log10(3.2e-4), digits = 2)

A pH of about 3.49: quite acidic, like orange juice.

And one with your own mean. Compute the mean of the titration volumes “by hand”, with sum() and length() instead of mean().

The mean is the total divided by the count: sum(titrations) divided by length(titrations).

titrations <- c(24.8, 25.1, 24.9, 25.3, 25.0)
sum(titrations) / length(titrations)

When R complains

Sooner or later, R will answer you with an error. That’s completely normal: experienced programmers see errors all day long. An error isn’t R saying “you’re bad at this”. It’s R saying “I didn’t understand, can you say that differently?” The message usually tells you exactly what went wrong.

You typed R says What it means
Reactor_temp object 'Reactor_temp' not found A typo or a capital letter, or you never created it
sqrt(16 unexpected end of input A parenthesis or quote was never closed
flow rate <- 5 unexpected symbol Something’s missing or extra. Here, the space in the name
sqrt("16") non-numeric argument Quotes make text, and you can’t take the square root of text

Try it: run this box and read the message. Then fix it.

Sometimes R gives you a warning instead. A warning means the code ran, but R suspects the answer isn’t what you wanted:

sqrt(-4)
#> Warning in sqrt(-4): NaNs produced
#> [1] NaN

The square root of a negative number isn’t a real number, so you get NaN (“not a number”) and a gentle warning. Never ignore a warning until you understand it.

Stuck on a function? In RStudio, type ?round (or any function name) to open its help page. The Examples at the bottom are often the most useful part. And anything after a # is a comment: R ignores it, so use comments to leave notes for yourself.

Your turn: fix the bug. This should work out the volume pumped in 8 minutes at 12.5 L/min, but it has one mistake.

Read the error. Which object can’t R find? Compare it with how that object was spelled when it was created.

flow_rate <- 12.5
time_min <- 8
volume_L <- flow_rate * time_min
volume_L

Flow_rate has a capital F, but the object is called flow_rate.

Challenge round

Feeling good? These two use everything from today. They’re harder, so take your time and use the hints.

Challenge 1 · Why water boils at 100 °C. The Antoine equation gives the vapor pressure of a liquid at temperature T (in °C): \log_{10} P = A - \frac{B}{C + T} , with P in mmHg. For water, A = 8.07131, B = 1730.63 and C = 233.426. Compute water’s vapor pressure at 100 °C.

The equation gives \log_{10} P, so you need to undo the log: P = 10^{\,A - B/(C + T)}.

In R: 10^(A - B / (C + temp_C)). The parentheses around C + temp_C matter!

A <- 8.07131
B <- 1730.63
C <- 233.426
temp_C <- 100
10^(A - B / (C + temp_C))

About 760 mmHg, which is exactly 1 atmosphere. A liquid boils when its vapor pressure equals the pressure around it, so water boils at 100 °C at sea level.

Challenge 2 · The pH of a vinegar solution. Acetic acid, the acid in vinegar, only partly dissociates in water. For a 0.10 mol/L solution, the hydrogen-ion concentration x solves the quadratic equation x^2 + K_a x - K_a c = 0, \qquad K_a = 1.8 \times 10^{-5} . Use the quadratic formula, x = \dfrac{-K_a + \sqrt{K_a^2 + 4K_a c}}{2}, then find the pH.

Translate the formula piece by piece: (-Ka + sqrt(Ka^2 + 4 * Ka * conc)) / 2.

Ka <- 1.8e-5
conc <- 0.10
h_plus <- (-Ka + sqrt(Ka^2 + 4 * Ka * conc)) / 2
-log10(h_plus)

A pH of about 2.88. Household vinegar is about eight times more concentrated, and its pH is around 2.4.

Quick quiz

Six quick questions to check your understanding. Tap an answer to see if you’re right.

1. What does 2 + 3 * 2 give?

Multiplication goes first: 3 * 2 is 6, then 2 + 6 is 8. For 10 you’d need (2 + 3) * 2.

2. Which of these is a valid object name?

Names must start with a letter and can’t contain spaces or hyphens. R would read inlet-pressure as “inlet minus pressure”.

3. You run Yield <- 85 and then yield + 5. What happens?

Capitals matter. Yield exists, but yield doesn’t.

4. What does round(2.567, digits = 1) give?

One decimal place, and 2.567 is closer to 2.6 than to 2.5.

5. What does log10(1000) give?

10^3 = 1000, so \log_{10}(1000) = 3. About 6.9 is the natural log, log(1000).

6. R prints an answer and a warning. What does that mean?

Warnings don’t stop the code; errors do. A warning is R saying “this worked, but take another look”.

Wrap-up

That’s your first lesson done. Here’s what you can do now:

  • Calculate: R handles arithmetic, powers and scientific notation, with parentheses to control the order.
  • Name things: <- stores a value in an object, and capital letters matter.
  • Use functions: round(), sqrt(), log10(), mean() and many more, with arguments that can have defaults.
  • Stay calm with errors: the message usually says exactly what’s wrong, and a warning means “take another look”.
TipPractice in RStudio (optional, about 30 minutes)

The live boxes are perfect for learning, but real work happens in RStudio on your own computer.

  1. Look around. Open RStudio. You’ll see the Console (where code runs), and once you open a script, the Source pane where you write it. Environment (top right) lists your objects.
  2. Start clean every time. Go to Tools → Global Options → General, untick Restore .RData into workspace at startup, and set Save workspace to .RData on exit to Never.
  3. Make a course folder, for example Documents/stats-course.
  4. Write a script. Choose File → New File → R Script and save it as week01.R in that folder. Type the ideal gas example with named objects, then run each line with Ctrl + Enter (Cmd + Enter on a Mac). Watch the Environment pane fill up.
  5. Read a help page. Run ?mean. What does its trim argument do? Try mean(c(1, 2, 3, 100), trim = 0.25). (You should get 2.5: trimming drops the extreme values 1 and 100.)
NoteKey words from this lesson
Console
Where R code runs and answers appear.
Script
A file of R code (ending in .R) that you can save and rerun.
Object
A named value stored in R, created with <-.
Function
A built-in tool such as sqrt() or mean() that takes arguments and returns an answer.
Argument and default
An input to a function, and the value it uses when you don’t give one.
Error and warning
An error stops your code. A warning lets it finish but flags something to check.
