Programming basics

Decisions, loops and your own functions

Make decisions with if and else, repeat work with loops, simulate a reactor step by step, write your own functions, apply them with sapply(), and debug code calmly.

Module 0 · Lesson 4 of 14 Week 4 of 160 About 5–7 hours

So far you’ve typed commands one at a time. Real engineering calculations need more than that: checking whether each batch meets spec, stepping a reactor model forward minute by minute, or packaging a calculation you do every week into a tool of your own. That’s programming, and it comes down to four building blocks: decisions, loops, functions and the apply family. Plus one skill that matters more than all of them: fixing code that doesn’t work.

Programming sounds scary, but it’s really just writing down a procedure, like a lab protocol. “If the pH is above 7, add acid. Repeat until it’s neutral.” You already think like this!

In this lesson you’ll:

  • make decisions with if, else and ifelse()
  • repeat work with for and while loops
  • simulate a reactor, one minute at a time
  • write your own functions
  • apply a function to every column with sapply()
  • track down bugs calmly

Making decisions

An if statement runs code only when a condition is true:

purity <- 98.9
if (purity >= 98.5) {
  "on spec"
} else {
  "off spec"
}
#> [1] "on spec"

The condition goes in parentheses and must be a single TRUE or FALSE. If it’s TRUE, the code in the first pair of braces runs. Otherwise the else part runs. (else is optional: without it, nothing happens when the condition is FALSE.)

For more than two outcomes, chain conditions with else if. R checks them from top to bottom and runs the first branch whose condition is TRUE:

pH <- 8.2
if (pH < 6.5) {
  "too acidic: add base"
} else if (pH <= 7.5) {
  "in range"
} else {
  "too basic: add acid"
}
#> [1] "too basic: add acid"

Try different pH values here, including exactly 6.5 and exactly 7.5. Which branch do they land in?

Your turn. Fill in the condition so the code says "on spec" when the purity is at least 98.5%.

purity <- 98.9

  "on spec"

One value or many?

if looks at exactly one value. Give it a whole vector, and R stops with an error:

purities <- c(98.9, 98.2, 99.1)
if (purities >= 98.5) "on spec"
#> Error in `if (purities >= 98.5) ...`:
#> ! the condition has length > 1

For a vector, use ifelse(). It takes a condition, the value to use where it’s TRUE, and the value to use where it’s FALSE, and it works element by element:

ifelse(purities >= 98.5, "on spec", "off spec")
#> [1] "on spec"  "off spec" "on spec"

To combine conditions inside if, use && (and) and || (or), which work on single values. Their one-character cousins & and |, from Lesson 2, work element by element on vectors.

Your turn. Label every batch in purities as "on spec" (98.5 or more) or "off spec".

ifelse(condition, value_if_true, value_if_false)

purities <- c(98.9, 98.2, 99.1, 98.5, 97.8)
ifelse(purities >= 98.5, "on spec", "off spec")

Exactly 98.5 counts as on spec, because the condition is “greater than or equal to”.

Loops: doing it again and again

A for loop runs the same code once for each value in a vector:

for (catalyst in c("A", "B", "C", "D")) {
  print(paste("Now testing catalyst", catalyst))
}
#> [1] "Now testing catalyst A"
#> [1] "Now testing catalyst B"
#> [1] "Now testing catalyst C"
#> [1] "Now testing catalyst D"

Read it as “for each value catalyst in c("A", "B", "C", "D"), run the code in the braces”. paste() glues text together with spaces in between. Inside a loop, R doesn’t print results automatically, so you need print().

Simulating a reactor

Here’s where loops really earn their keep. A reactant decomposes with first-order kinetics, with a rate constant k = 0.1 per minute: each minute, about 10% of what’s left reacts. Let’s follow its concentration for 10 minutes.

Most of the time you’ll want to keep every result, so first create an empty vector of the right length (that’s called preallocating), then fill it in:

conc <- numeric(11)      # room for minute 0 up to minute 10
conc[1] <- 1.0           # start at 1.0 mol/L
for (i in 2:11) {
  conc[i] <- conc[i - 1] - 0.1 * conc[i - 1]    # lose 10% each minute
}
round(conc, 3)
#>  [1] 1.000 0.900 0.810 0.729 0.656 0.590 0.531 0.478 0.430 0.387 0.349

Each step depends on the one before it. That’s exactly when loops shine. When the steps don’t depend on each other, vectorized code is shorter and faster: here, 0.9^(0:10) gives exactly the same numbers.

NoteGo deeper: the loop is solving a differential equation

First-order kinetics means \dfrac{dC}{dt} = -kC, and calculus gives the exact solution C(t) = C_0 e^{-kt}. The loop takes a different route. It steps forward in small jumps of \Delta t, assuming the rate stays constant during each jump:

C(t + \Delta t) \approx C(t) - k\,C(t)\,\Delta t .

This is Euler’s method, the simplest way to solve a differential equation numerically. With k = 0.1 and \Delta t = 1 minute, the loop says 0.349 mol/L after 10 minutes, while the exact answer is e^{-1} \approx 0.368. Smaller steps get closer to the truth. That idea is behind every numerical ODE solver, including the ones engineers use to design real reactors.

Your turn. Five continuous stirred-tank reactors are connected in series. Each one converts 30% of the reactant flowing into it, so 70% passes on to the next. Use the loop to fill left with the fraction of reactant remaining after each reactor.

Each reactor lets 70% of what enters it pass through: multiply remaining by 0.7.

left <- numeric(5)
remaining <- 1
for (i in 1:5) {
  remaining <- remaining * 0.7
  left[i] <- remaining
}
left

After five reactors, about 17% of the reactant is still left, so the overall conversion is 83%.

TipUse seq_along(), not 1:length(x)

To loop over the positions of a vector, write for (i in seq_along(x)). If x happens to be empty, 1:length(x) is 1:0, which is c(1, 0), and the loop runs twice when it shouldn’t run at all.

Repeating until something happens

A while loop repeats for as long as its condition stays TRUE. It’s the right tool when you don’t know in advance how many repetitions you’ll need. How many minutes until our reactant falls below half its starting concentration?

conc <- 1.0
minutes <- 0
while (conc > 0.5) {
  conc <- conc - 0.1 * conc
  minutes <- minutes + 1
}
minutes
#> [1] 7

Seven minutes, close to the exact half-life of \ln 2 / k \approx 6.9 minutes.

Make sure the condition eventually becomes FALSE, or the loop runs forever! In RStudio, press Esc to stop a runaway loop. The live boxes here give up after 30 seconds. Two more keywords give you control: break leaves a loop immediately, and next skips straight to the next round.

Your turn. Back to the reactors in series, each converting 30%. How many do you need to convert at least 99% of the reactant? That means that less than 1% (0.01) is left.

Keep adding reactors while the fraction left is still above 0.01.

left <- 1
reactors <- 0
while (left > 0.01) {
  left <- left * 0.7
  reactors <- reactors + 1
}
reactors

After 12 reactors, 1.4% is still left. The 13th brings it below 1%.

Writing your own functions

When you find yourself doing the same calculation again and again, wrap it in a function. Here’s the ideal gas law, solved for the number of moles:

moles <- function(P_Pa, V_m3, T_K) {
  P_Pa * V_m3 / (8.314 * T_K)
}
moles(101325, 0.05, 298.15)
#> [1] 2.043816
moles(P_Pa = 200000, V_m3 = 0.05, T_K = 298.15)
#> [1] 4.034179

A function has a name (moles), arguments in the parentheses after function, and a body in braces. The value of the last line of the body is what the function gives back. (You can also leave early with return(value).)

Because the body uses vectorized arithmetic, your function works on whole vectors for free. Here’s a tank at three different temperatures:

moles(101325, 0.05, c(273.15, 298.15, 373.15))
#> [1] 2.230876 2.043816 1.633026

Your turn. Analytical chemists judge how precise their replicate measurements are with the relative standard deviation (RSD): the standard deviation as a percentage of the mean. Write rsd().

The body is one line: sd(x) divided by mean(x), times 100.

rsd <- function(x) {
  100 * sd(x) / mean(x)
}
rsd(c(10.2, 10.5, 9.9, 10.1, 10.3))

About 2.2%: the replicates agree within a couple of percent.

Your turn. Complete classify_temp(): below 170 °C the reactor is "too cold", from 170 up to and including 190 it’s "in range", and above 190 it’s "too hot".

By the time R reaches else if, it already knows the temperature is at least 170. So the only thing left to check is whether it’s at most 190.

classify_temp <- function(temp_C) {
  if (temp_C < 170) {
    "too cold"
  } else if (temp_C <= 190) {
    "in range"
  } else {
    "too hot"
  }
}
classify_temp(182)

Defaults and scope

Give an argument a default with =, and you can leave it out when you call the function. The gas constant is a perfect example: it’s almost always 8.314 J/(mol·K), but sometimes you’d rather work in liters and atmospheres:

moles <- function(P, V, T_K, R = 8.314) {
  P * V / (R * T_K)
}
moles(101325, 0.05, 298.15)                   # Pa and m³, the default R
#> [1] 2.043816
moles(1, 50, 298.15, R = 0.082057)            # atm and liters
#> [1] 2.043711

Same answer, about 2.04 mol, in two unit systems.

What happens inside stays inside

Objects created inside a function exist only while it runs. This is called scope, and it means a function can’t accidentally overwrite your own objects:

f <- function() {
  inside <- 42
  inside * 2
}
f()
#> [1] 84
exists("inside")
#> [1] FALSE

Failing clearly

A good function stops with a helpful message when it’s given the wrong kind of input. stop() ends the function with your own error message:

rsd <- function(x) {
  if (!is.numeric(x)) stop("rsd() needs numbers, but got ", class(x))
  100 * sd(x) / mean(x)
}
rsd(c(10.2, 10.5, 9.9))
#> [1] 2.941176
rsd("ten")
#> Error in `rsd()`:
#> ! rsd() needs numbers, but got character

Your turn. Complete to_kelvin(). By default it converts from Celsius. With scale = "F" it converts from Fahrenheit: subtract 32, multiply by 5/9, then add 273.15.

Translate the recipe directly: (temp - 32) * 5 / 9 + 273.15.

to_kelvin <- function(temp, scale = "C") {
  if (scale == "C") {
    temp + 273.15
  } else {
    (temp - 32) * 5 / 9 + 273.15
  }
}
to_kelvin(25)
to_kelvin(212, scale = "F")

212 °F is the boiling point of water, 373.15 K.

Every column at once: sapply()

sapply() applies a function to each element of a vector, and collects the results:

sapply(c(4, 9, 16), sqrt)
#> [1] 2 3 4

A data frame is a set of columns, so sapply() over a data frame applies the function to every column. That’s a quick way to summarize a whole dataset:

sapply(stackloss, mean)
#>   Air.Flow Water.Temp Acid.Conc. stack.loss 
#>   60.42857   21.09524   86.28571   17.52381

You can also write a function right where you use it, without giving it a name. That’s called an anonymous function. Here’s the coefficient of variation of every column, using the RSD formula from before:

sapply(stackloss, function(col) 100 * sd(col) / mean(col))
#>   Air.Flow Water.Temp Acid.Conc. stack.loss 
#>  15.172075  14.983341   6.210265  58.044585

Since R 4.1, you can shorten function(col) to \(col), so sapply(stackloss, \(col) max(col)) works too. And lapply() does the same job as sapply(), but always returns a list (Lesson 1.2 covers lists).

Which tool should you reach for?

Situation Best tool
The same arithmetic on every element Vectorized code, like x * 2 or sqrt(x)
A function on every element or column sapply() or lapply()
Each step depends on the one before A for loop
You don’t know how many steps you’ll need A while loop

Your turn. Use sapply() with your own anonymous function to find the range of each column of stackloss: the maximum minus the minimum.

For one column, the range is max(col) - min(col).

sapply(stackloss, function(col) max(col) - min(col))

When code doesn’t work

Everyone’s code breaks, all the time. What separates beginners from experts isn’t fewer bugs. It’s a calm, step-by-step way of fixing them:

  1. Read the error message. It says what went wrong, and usually where.
  2. Find the line. Run the code one line at a time until it breaks.
  3. Look inside. Print the objects involved, or check them with str() and class().
  4. Make it smaller. Reproduce the problem with the simplest input you can.
  5. Check your assumptions. Is it the type you think? The length? Any NAs? Spelled the same way?

Here’s a function with a bug. Read the message: it names the culprit.

standardize <- function(x) {
  (x - mean(x)) / sd(X)
}
standardize(c(176, 180, 184))
#> Error in `standardize()`:
#> ! object 'X' not found

Some bugs are so common that it’s worth checking for them first:

Bug Example
Wrong spelling or capital letters sd(X) when the object is x
A missing parenthesis, comma or quote mean(c(1, 2)
= where you meant == if (x = 5)
Forgetting na.rm = TRUE mean(batches$temp_C) gives NA
Not saving a result x + 1 prints a value but doesn’t change x. You need x <- x + 1

The sneakiest bugs don’t cause errors at all: the code runs and quietly gives a wrong answer. So always ask, “does this number make sense?” A yield of 250% or a negative concentration is a bug, not a discovery!

Your turn: fix the bug. This function should summarize a set of yields, but one reading is missing, so it gives NA. Fix the function so it ignores missing values.

Both mean() and max() need to be told to leave out missing values.

yield_summary <- function(x) {
  c(mean = mean(x, na.rm = TRUE), max = max(x, na.rm = TRUE))
}
yield_summary(c(61.2, NA, 58.4, 63.0))

Challenge round

Challenge 1 · Simulate a batch reactor. A reactant starts at 2.0 mol/L and decomposes with first-order kinetics, with k = 0.05 per minute. Use a loop with one-minute steps, like the one earlier in the lesson, to find the concentration after 30 minutes.

Each minute, the concentration drops by k times the current concentration. The current concentration is conc[i - 1].

conc[i] <- conc[i - 1] - k * ______

k <- 0.05
conc <- numeric(31)    # minute 0 up to minute 30
conc[1] <- 2.0
for (i in 2:31) {
  conc[i] <- conc[i - 1] - k * conc[i - 1]
}
conc[31]

About 0.429 mol/L. The exact answer, 2.0\,e^{-0.05 \times 30}, is 0.446. One-minute steps are a little coarse, so try half-minute steps and see the gap shrink. Add plot(0:30, conc) to see the decay curve.

Challenge 2 · The most common value. R has no built-in function for the mode, the value that appears most often. Complete stat_mode() using table(), which.max() and names(). Test it on a week’s alarm counts.

which.max(counts) gives the position of the biggest count, labeled with its value. Run counts and which.max(counts) on their own to see what they look like.

names(which.max(counts)) gives the most common value, but as text, like "1". Turn it back into a number with as.numeric().

stat_mode <- function(x) {
  counts <- table(x)
  as.numeric(names(which.max(counts)))
}
alarms <- c(1, 0, 2, 1, 1, 3, 0, 1)
stat_mode(alarms)

When two values tie, which.max() picks the first, so this function reports the smaller one.

Quick quiz

1. x <- c(3, 8). What happens when you run if (x > 5) "big"?

if needs exactly one TRUE or FALSE. For a vector, use ifelse(x > 5, "big", "small").

2. What does ifelse(c(98.9, 97.2, 99.0) >= 98.5, "on", "off") return?

ifelse() works element by element: 97.2 is the only value below 98.5.

3. How many times does for (i in 2:5) print(i) print something?

2:5 is 2, 3, 4, 5: four values, so four rounds.

4. A function has no return(). What does it give back?

R returns the last value computed. You only need return() to leave a function early.

5. Given f <- function(x, y = 2) x^y, what is f(3)?

y defaults to 2, so f(3) is 3^2 = 9. f(3, 3) would be 27.

6. Your code stops with an error. What should you do first?

The message almost always names the problem, and often the object or function involved. Start there.

Wrap-up

You can program now! Here’s what you can do:

  • Decide: if/else chooses what to do for one value, and ifelse() does it for a whole vector.
  • Repeat: for runs once per value, and while runs until a condition fails. Preallocate your results and fill them in.
  • Simulate: a loop that steps forward in time is how engineers solve rate equations numerically.
  • Build tools: function() makes your own functions, with defaults, and keeps their objects to themselves.
  • Summarize everything: sapply() applies a function to every column.
  • Debug calmly: read the message, find the line, look inside, and make it smaller.

NoteKey words from this lesson
Condition
An expression that is TRUE or FALSE, used by if and while to decide what to do.
Loop
Code that repeats: for runs once per value of a vector, and while runs until its condition is false.
Preallocation
Creating a result vector of the right size before a loop fills it in.
Function
A reusable piece of code with arguments and a return value, created with function().
Default value
The value an argument takes when you don’t supply one.
Scope
Where an object can be seen. Objects made inside a function are visible only inside it.
Anonymous function
A function written right where it’s used, without a name, such as function(col) max(col).
Euler’s method
Solving a rate equation numerically by stepping forward in small time steps.
Debugging
Finding and fixing the cause of code that fails or gives wrong results.
