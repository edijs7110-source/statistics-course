Data frames

Tables of data: one row per batch, one column per measurement

Describe data as observations and variables, build and inspect data frames, pick rows and columns, summarize by group, and read a CSV file.

Module 0 · Lesson 3 of 14 Week 3 of 160 About 5–7 hours

In the lab, you never write down just one number. For every batch you note the catalyst, the temperature, how long it ran, the yield, the purity… One line per batch, one column per measurement. That’s a table, and in R a table is called a data frame. It’s the object you’ll use most for the rest of the course.

This lesson also introduces a dataset we’ll keep coming back to: 40 batches from a pilot-plant reactor. By the end, you’ll be answering real questions about it, like which catalyst works best.

In this lesson you’ll:

  • describe data as rows (observations) and columns (variables)
  • build a data frame and look inside it
  • pick out the rows and columns you need
  • summarize by group, like the average yield for each catalyst
  • read a data file and track down its missing values

Rows and columns

Two words describe the shape of almost every dataset:

  • An observation is one row: one thing you collected data on, such as a batch. It’s also called a case or a record.
  • A variable is one column: one thing you recorded about it, which varies from row to row.

Here’s a tiny dataset: four runs of a lab experiment that tests two catalysts at two temperatures.

run catalyst temp_C yield_pct
1 A 160 52.1
2 B 160 55.8
3 A 180 60.4
4 B 180 63.0

Variables come in types, and the type decides what you can sensibly do with them:

Numerical variables are measured or counted.
Continuous ones can take any value in a range, like temperature, yield or purity. Discrete ones are counts, like the number of alarms during a batch.
Categorical variables sort the rows into groups.
Nominal ones have no natural order, like catalyst A or B, or the day or night shift. Ordinal ones do, like an agitator set to low, medium or high.

An average catalyst is nonsense, but the proportion of batches that used catalyst A isn’t. And watch out for numbers that are really labels: batch numbers, pump IDs and CAS numbers (water’s is 7732-18-5) are categorical, however numeric they look.

Your first data frame

data.frame() builds a data frame out of vectors, one per column:

runs <- data.frame(
  run = 1:4,
  catalyst = c("A", "B", "A", "B"),
  temp_C = c(160, 160, 180, 180),
  yield_pct = c(52.1, 55.8, 60.4, 63.0)
)
runs
#>   run catalyst temp_C yield_pct
#> 1   1        A    160      52.1
#> 2   2        B    160      55.8
#> 3   3        A    180      60.4
#> 4   4        B    180      63.0

A data frame is just a set of vectors of the same length, standing side by side. Everything you learned about vectors still works on each column. Different columns can hold different types (text for the catalyst, numbers for the yield), but within one column, every value has the same type.

NoteGo deeper: what a data frame really is

Under the hood, a data frame is a list of columns, with the rule that all the columns have the same length. That explains a slightly odd result:

typeof(runs)
#> [1] "list"
length(runs)
#> [1] 4

length() of a data frame is its number of columns, because it counts the items in the list. Use nrow() for the number of rows. You’ll learn about lists properly in Lesson 1.2.

Looking inside

R comes with built-in datasets to practice on, and one of them is pure chemical engineering. stackloss holds 21 days of data from a plant that makes nitric acid by oxidizing ammonia. head() shows the first six rows:

head(stackloss)
#>   Air.Flow Water.Temp Acid.Conc. stack.loss
#> 1       80         27         89         42
#> 2       80         27         88         37
#> 3       75         25         90         37
#> 4       62         24         87         28
#> 5       62         22         87         18
#> 6       62         23         87         18
Column What it measures
Air.Flow how hard the plant was running
Water.Temp the temperature of the cooling water, in °C
Acid.Conc. the acid concentration, coded: 89 means 58.9% acid
stack.loss the ammonia that escaped up the stack unconverted, as 10 times the percentage: 42 means 4.2% was lost. Lower is better!

The numbers down the left side aren’t a column. They’re row names. A few functions describe a data frame’s size and shape:

dim(stackloss)       # rows, then columns
#> [1] 21  4
nrow(stackloss)
#> [1] 21
names(stackloss)
#> [1] "Air.Flow"   "Water.Temp" "Acid.Conc." "stack.loss"

The most useful of all is str(), short for structure. It lists every column with its type and first few values:

str(stackloss)
#> 'data.frame':    21 obs. of  4 variables:
#>  $ Air.Flow  : num  80 80 75 62 62 62 62 62 58 58 ...
#>  $ Water.Temp: num  27 27 25 24 22 23 24 24 23 18 ...
#>  $ Acid.Conc.: num  89 88 90 87 87 87 93 93 87 80 ...
#>  $ stack.loss: num  42 37 37 28 18 18 19 20 15 14 ...

Read the first line as “a data frame with 21 observations of 4 variables”. All four columns are num, which means numeric. Make str() a habit: run it on every dataset you meet, before anything else.

summary() gives a quick summary of every column at once:

summary(stackloss)
#>     Air.Flow       Water.Temp     Acid.Conc.      stack.loss   
#>  Min.   :50.00   Min.   :17.0   Min.   :72.00   Min.   : 7.00  
#>  1st Qu.:56.00   1st Qu.:18.0   1st Qu.:82.00   1st Qu.:11.00  
#>  Median :58.00   Median :20.0   Median :87.00   Median :15.00  
#>  Mean   :60.43   Mean   :21.1   Mean   :86.29   Mean   :17.52  
#>  3rd Qu.:62.00   3rd Qu.:24.0   3rd Qu.:89.00   3rd Qu.:19.00  
#>  Max.   :80.00   Max.   :27.0   Max.   :93.00   Max.   :42.00

In RStudio, View(stackloss) opens the data in a spreadsheet-style viewer, and ?stackloss explains every column. Working with columns

The dollar sign pulls a single column out of a data frame, as a vector:

stackloss$stack.loss
#>  [1] 42 37 37 28 18 18 19 20 15 14 14 13 11 12  8  7  8  8  9 15 15
mean(stackloss$stack.loss)
#> [1] 17.52381

So on average, about 1.75% of the ammonia escaped (17.52 divided by 10).

Adding a column is just as easy: assign to a new name after the $. Let’s store the loss as a real percentage. We’ll work on a copy called plant, so the original stays untouched:

plant <- stackloss
plant$loss_pct <- plant$stack.loss / 10
head(plant, 3)
#>   Air.Flow Water.Temp Acid.Conc. stack.loss loss_pct
#> 1       80         27         89         42      4.2
#> 2       80         27         88         37      3.7
#> 3       75         25         90         37      3.7

Picking rows and columns

A data frame has two dimensions, so square brackets take two positions, separated by a comma: [rows, columns]. Leave one empty to mean “all of them”:

runs[1, ]                            # row 1, every column
#>   run catalyst temp_C yield_pct
#> 1   1        A    160      52.1
runs[, "yield_pct"]                  # every row, one column
#> [1] 52.1 55.8 60.4 63.0
runs[2, "catalyst"]                  # row 2, the catalyst
#> [1] "B"
runs[, c("catalyst", "yield_pct")]   # two columns, by name
#>   catalyst yield_pct
#> 1        A      52.1
#> 2        B      55.8
#> 3        A      60.4
#> 4        B      63.0

The real power comes from conditions. Put a TRUE/FALSE question in the row position, and you keep the rows where the answer is TRUE:

runs[runs$temp_C == 180, ]
#>   run catalyst temp_C yield_pct
#> 3   3        A    180      60.4
#> 4   4        B    180      63.0

Read it as “runs, the rows where temp_C is 180, every column”. It’s the logical indexing from the last lesson, now picking whole rows.

To sort, order() gives the row positions in sorted order, and you use them as the row index:

runs[order(runs$yield_pct, decreasing = TRUE), ]
#>   run catalyst temp_C yield_pct
#> 4   4        B    180      63.0
#> 3   3        A    180      60.4
#> 2   2        B    160      55.8
#> 1   1        A    160      52.1

And subset() is a shortcut that lets you use the column names directly:

subset(runs, catalyst == "B", select = c(run, yield_pct))
#>   run yield_pct
#> 2   2      55.8
#> 4   4      63.0

In Lesson 6 you’ll meet dplyr, which makes all of this even easier to read. These base R tools are still worth knowing, because they work everywhere and you’ll see them in other people’s code.

WarningDon’t forget the comma

runs[runs$temp_C == 180], without the comma, gives an error (undefined columns selected), because a single index picks columns. To pick rows, write runs[runs$temp_C == 180, ].

Your turn. On which days did more than 2% of the ammonia escape? Careful with the units: stack.loss is 10 times the percentage. Return those rows, with every column.

The first four days, when the plant was running hardest. subset(stackloss, stack.loss > 20) works too.

Reading a data file

Real data usually arrives as a file, and the most common format is CSV, for comma-separated values. It’s plain text: the first line has the column names, and every other line is one observation, with commas between the values. Here are the first lines of the file we’ll use from now on:

cat(readLines("data/reactor_batches.csv", n = 4), sep = "\n")
#> "batch_id","shift","catalyst","temp_C","pressure_bar","residence_min","alarms","yield_pct","purity_pct","on_spec"
#> "B01","day","B",185.3,3.72,47.2,1,70.2,98.9,TRUE
#> "B02","day","D",176,5.31,37.9,1,53.7,98.7,TRUE
#> "B03","day","C",177.9,5.12,32.5,1,49.2,99.6,TRUE

read.csv() reads it into a data frame:

batches <- read.csv("data/reactor_batches.csv")
str(batches)
#> 'data.frame':    40 obs. of  10 variables:
#>  $ batch_id     : chr  "B01" "B02" "B03" "B04" ...
#>  $ shift        : chr  "day" "day" "day" "night" ...
#>  $ catalyst     : chr  "B" "D" "C" "B" ...
#>  $ temp_C       : num  185 176 178 184 180 ...
#>  $ pressure_bar : num  3.72 5.31 5.12 4.93 5.22 5.36 4.53 6.02 4.49 5.81 ...
#>  $ residence_min: num  47.2 37.9 32.5 60.7 41.1 47.1 64 38.9 38.8 21 ...
#>  $ alarms       : int  1 1 1 1 1 0 1 1 1 3 ...
#>  $ yield_pct    : num  70.2 53.7 49.2 65.3 53.4 58.5 74.1 55.3 56.4 31.1 ...
#>  $ purity_pct   : num  98.9 98.7 99.6 98.8 99.2 ...
#>  $ on_spec      : logi  TRUE TRUE TRUE TRUE TRUE TRUE ...

These are 40 batches from a pilot-plant reactor. The data is made up for this course, but it behaves like the real thing. Here’s what each column means:

Column What it is
batch_id the batch’s label, B01 to B40
shift which shift ran it: day or night
catalyst which of four catalysts was used: A, B, C or D
temp_C the reactor temperature, in °C
pressure_bar the reactor pressure, in bar
residence_min the residence time: how long the mixture stays in the reactor, in minutes
alarms how many process alarms went off during the batch
yield_pct the yield: how much product you got, as a percentage of the theoretical maximum
purity_pct the purity of the product, in %
on_spec TRUE if the purity met the 98.5% spec

read.csv() guessed each column’s type from what’s in it: chr (text) for the shift, num for the temperature, int (whole numbers) for the alarms, and logi (TRUE/FALSE) for on_spec. Always check with str() after reading a file. A wrong type is often the first clue that something’s off in the data, like the “n/a” from the last lesson.

Summaries by group

Now for the questions engineers actually ask. Which catalyst gives the best yield? Does the night shift run differently? table() counts each category, and with two variables it counts every combination:

table(batches$catalyst)
#> 
#>  A  B  C  D 
#> 10 12  9  9
table(batches$shift, batches$on_spec)
#>        
#>         FALSE TRUE
#>   day       6   16
#>   night     3   15

The second one is called a contingency table. Of the 22 day-shift batches, 6 were off spec (FALSE) and 16 were on spec.

To summarize a number separately for each group, use tapply() or aggregate():

tapply(batches$yield_pct, batches$catalyst, mean)
#>        A        B        C        D 
#> 59.98000 55.72500 54.80000 60.46667
aggregate(yield_pct ~ catalyst, data = batches, FUN = mean)
#>   catalyst yield_pct
#> 1        A  59.98000
#> 2        B  55.72500
#> 3        C  54.80000
#> 4        D  60.46667

Both give the mean yield for each catalyst. Catalysts A and D come out ahead at about 60%, with B and C closer to 55%. Whether those differences are real or just batch-to-batch noise is a question for Lesson 13!

aggregate() uses a formula, yield_pct ~ catalyst, which you read as “yield by catalyst”. You’ll see the tilde ~ all over R’s statistical functions: every regression model in Module 2 is written as a formula.

Your turn. Compute the on-spec rate, the proportion of batches on spec, for each catalyst.

Remember from the last lesson: the mean of TRUE/FALSE values is the proportion of TRUEs. So use tapply() with the on_spec column, grouped by catalyst, and mean.

tapply(batches$on_spec, batches$catalyst, mean)

aggregate(on_spec ~ catalyst, data = batches, FUN = mean) gives the same numbers as a data frame.

Missing values in a data frame

Real data has gaps, and this dataset is no exception. colSums(is.na(...)) counts the missing values in every column at once:

colSums(is.na(batches))
#>      batch_id         shift      catalyst        temp_C  pressure_bar 
#>             0             0             0             2             0 
#> residence_min        alarms     yield_pct    purity_pct       on_spec 
#>             0             1             0             0             0

The temperature sensor dropped out twice, and one batch’s alarm log was lost.

Missing values cause a sneaky problem when you pick rows with a condition. For a batch with no temperature, batches$temp_C > 185 is NA, and R hands you back a row full of NAs for it:

nrow(batches[batches$temp_C > 185, ])          # 14 rows, but 2 of them are all NA
#> [1] 14
nrow(subset(batches, temp_C > 185))            # only the 12 real matches
#> [1] 12
nrow(batches[which(batches$temp_C > 185), ])   # which() also skips the NAs
#> [1] 12

subset() and which() quietly drop the rows where the answer is unknown. na.omit() goes further, and drops every row with any missing value:

nrow(na.omit(batches))
#> [1] 37

That loses 3 of the 40 batches. Sometimes that’s fine. But if values are missing for a reason (say, the sensor fails only when the reactor runs hot), dropping them can bias your results. Module 1 has two whole lessons on this.

Your turn. Return the batches that ran hotter than 185 °C, with only their batch_id, temp_C and purity_pct. No NA rows allowed!

subset() takes the data, a condition, and select = c(...) for the columns. It drops the rows where the condition is NA for you.

subset(batches, temp_C > 185, select = c(batch_id, temp_C, purity_pct))

With square brackets: batches[which(batches$temp_C > 185), c("batch_id", "temp_C", "purity_pct")].

Challenge round

Challenge 1 · Does a longer stay pay off? The residence time is how long the mixture spends in the reactor. Compute the mean yield separately for batches with residence times of 45 minutes or less, and more than 45 minutes.

batches$residence_min > 45 splits the batches into two groups, FALSE and TRUE. You can use it as the groups in tapply().

tapply(batches$yield_pct, batches$residence_min > 45, ______)

tapply(batches$yield_pct, batches$residence_min > 45, mean)

With logical indexing instead:

c(mean(batches$yield_pct[batches$residence_min <= 45]),
  mean(batches$yield_pct[batches$residence_min > 45]))

About 53% for the short stays and 63% for the long ones. More time in the reactor means more of the reactants get converted.

Challenge 2 · The temperature trade-off. A hotter reactor runs faster, but it often makes more by-products, which lowers the purity. Compare the on-spec rate of the batches that ran hotter than 185 °C with the rest. Watch out: two batches have no temperature.

It’s the same idea as Challenge 1, with on_spec as the values and temp_C > 185 as the groups. The mean of on_spec is the on-spec rate.

tapply() simply leaves out the batches whose group is NA. If you use logical indexing instead, you’ll need na.rm = TRUE or which().

tapply(batches$on_spec, batches$temp_C > 185, mean)

About 96% of the cooler batches were on spec, but only a third of the hot ones. That’s a real trade-off engineers face: push the temperature for speed, and pay for it in purity.

Quick quiz

1. In the batches data, each row is…

Rows are observations (the things you collected data on), and columns are variables (what you recorded about them).

2. Which of these variables is ordinal?

The agitator settings are categories with a natural order. Catalyst type and batch ID are categories with no order, and purity is numerical.

3. What does batches[2, ] return?

Inside [rows, columns], an empty column position means “all the columns”.

4. You run batches[batches$yield_pct > 70]. What happens?

A single index picks columns. To pick rows, add the comma: batches[batches$yield_pct > 70, ].

5. What does aggregate(purity_pct ~ shift, data = batches, FUN = mean) compute?

Read the formula purity_pct ~ shift as “purity by shift”: the mean purity within each shift.

6. Only 12 batches ran above 185 °C, yet batches[batches$temp_C > 185, ] returns 14 rows. Why?

For a missing temperature, the condition is NA, so R returns a row of NAs. subset() and which() avoid this.

Wrap-up

Great job: you can now work with real tables of data. Here’s what you can do:

  • Think in rows and columns: observations and variables, and the types of variables (continuous, discrete, nominal, ordinal).
  • Build and inspect data frames with data.frame(), str(), head(), summary() and dim().
  • Pick what you need: $ pulls out a column, and [rows, columns] picks by position, name or condition. Don’t forget the comma!
  • Summarize by group with table(), tapply() and aggregate().
  • Load data from a CSV file with read.csv(), then check it with str() and colSums(is.na()).

NoteKey words from this lesson
Observation
One row of a dataset: one thing data was collected on.
Variable
One column of a dataset: a characteristic that varies across observations.
Numerical variable
A measured quantity, either continuous (any value in a range) or discrete (a count).
Categorical variable
A variable that sorts observations into groups, either nominal (no order) or ordinal (ordered).
Data frame
R’s object for a table of data, made of equal-length column vectors.
CSV file
A plain-text table with commas between the values and the column names on the first line.
Working directory
The folder R looks in when you give it a relative file path.
Contingency table
A table that counts the observations in every combination of two categorical variables.
Formula
An expression with ~, like yield_pct ~ catalyst, describing how variables relate. Read the tilde as “by”.
