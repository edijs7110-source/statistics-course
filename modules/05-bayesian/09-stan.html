Probabilistic programming with Stan

Write the model, let Stan do the sampling

Meet Stan, the language and sampler used for most Bayesian work today. Read a Stan program block by block, the pumps’ censored Weibull model from Module 4, and fit it from R with cmdstanr. Then fit the flammability model with one line of brms, read the output, and work with the saved posterior draws in the browser: summaries, convergence checks, Monte Carlo errors and predictions.

Module 5 · Lesson 9 of 13 Week 84 of 160 About 5–7 hours

In Module 4, sampling the pumps’ posterior took a page of R: the log-likelihood with its censoring, the log-prior, a Metropolis sampler, its tuning, and the convergence checks. And every new model would need all of that again, by hand.

Stan turns that around. You write down the model, the data, the parameters, the priors and the likelihood, in a short program, and Stan does the rest: it computes the gradient by automatic differentiation, runs Lesson 8’s Hamiltonian Monte Carlo with an adaptive trajectory length (the No-U-Turn Sampler, NUTS), tunes the step size and the mass matrix during warmup, and reports the diagnostics. It’s what most Bayesian analyses in science and engineering use today. And brms goes one step further: it writes the Stan program for you, from an R formula like the ones you used with lm() and glm() in Module 2.

Stan compiles each model to C++, so it can’t run in your browser. This lesson shows the Stan programs and their output, fitted on a computer, and the live exercises work with the saved posterior draws. The practice section at the end says how to install Stan, so you can fit the models yourself in RStudio.

Stan is named after Stanislaw Ulam, one of the inventors of the Monte Carlo method. He came up with it while playing solitaire, wondering how often a hand would come out. Games, again!

A Stan program

Here is Module 4’s pumps model in Stan: a Weibull lifetime distribution, with some pumps still running (right-censored), and Module 4’s priors. You can download it.

// Weibull lifetimes with right-censoring: Module 4's pumps, with Module 4's priors
data {
  int<lower=0> N;                          // number of pumps
  vector<lower=0>[N] days;                 // days to failure, or to the end of the study
  array[N] int<lower=0, upper=1> failed;   // 1 = failed, 0 = still running (censored)
}
parameters {
  real log_shape;
  real log_scale;
}
transformed parameters {
  real<lower=0> shape = exp(log_shape);
  real<lower=0> scale = exp(log_scale);
}
model {
  log_shape ~ normal(0, 1);                // priors
  log_scale ~ normal(7.5, 1);
  for (i in 1:N) {                         // likelihood
    if (failed[i] == 1) {
      target += weibull_lpdf(days[i] | shape, scale);
    } else {
      target += weibull_lccdf(days[i] | shape, scale);
    }
  }
}
generated quantities {
  real b10 = scale * pow(-log(0.9), 1 / shape);   // the B10 life, in days
}

Each block has one job:

  • data declares what you’ll pass in from R, with types and constraints. Stan checks them, so a negative number of days is an error, not a silent bug.
  • parameters declares the unknowns that Stan samples.
  • transformed parameters computes functions of them that the model uses, and saves them in the output.
  • model builds the log-posterior. x ~ normal(0, 1) adds the normal log-density to it, and target += ... adds anything you like. Here, a failed pump adds the Weibull log-density (_lpdf), and a censored one adds the log of the probability of surviving that long, the complementary CDF (_lccdf). That’s the censored likelihood from Module 4, Lesson 9, in two lines.
  • generated quantities computes things from each draw after sampling, such as the B10 life, or simulated data for posterior predictive checks.

Stan is a typed language, a bit like C: every variable has a declared type, statements end with semicolons, and comments start with //.

Fitting it from R

The cmdstanr package compiles the program and runs the sampler. This code ran on a computer with Stan installed:

library(cmdstanr)
pumps <- read.csv("data-raw/pump_field.csv")
model <- cmdstan_model("pumps.stan")                      # compile to C++ (takes a minute, once)
fit <- model$sample(
  data = list(N = nrow(pumps), days = pumps$days, failed = pumps$failed),
  seed = 5091, chains = 4, parallel_chains = 4
)
fit$summary(c("shape", "scale", "b10"))
fit$diagnostic_summary()

By default, it ran 4 chains, each with 1,000 warmup iterations (discarded, used to tune the sampler) and 1,000 kept draws: 4,000 posterior draws in all. Here is the summary:

Your turn. The setup code has Stan’s 4,000 draws in pumps_draws, with columns chain, iteration, shape, scale and b10. Find the posterior mean and 95% credible interval of the shape. Module 4’s hand-written Metropolis sampler gave 1.86 (1.26 to 2.48).

The column is shape.

c(mean = mean(pumps_draws$shape), quantile(pumps_draws$shape, c(0.025, 0.975)))

A posterior mean of 1.863, with a 95% credible interval from 1.32 to 2.49: the same posterior as Module 4’s, within Monte Carlo error. Two samplers, one posterior. That’s the most reassuring check there is, and it’s worth doing whenever you write your first Stan version of a model you’ve fitted another way.

Your turn. The Stan program computed the B10 life for every draw, in its generated quantities block. What’s the posterior probability that it’s longer than a year?

A year is 365 days.

c(mean = mean(pumps_draws$b10), p_over_a_year = mean(pumps_draws$b10 > 365))

A posterior mean of 527 days, and a 93% probability that it’s more than a year. Module 4 got 91% from its 9,000 Metropolis draws, which were worth only about 700 independent ones; Stan’s 4,000 are worth about 2,400. The difference is within Monte Carlo error.

Checking the draws yourself

The posterior package, from Lesson 8, reads draws in a standard format. as_draws_df() wants the chain and iteration in columns named .chain and .iteration, and then summarise_draws() gives the same summary as Stan, with any statistics you ask for.

Your turn. Convert the pumps draws, and summarize the shape and scale with their mean, SD, R-hat, and bulk and tail ESS.

The iteration number is in pumps_draws$iteration.

draws <- posterior::as_draws_df(data.frame(shape = pumps_draws$shape, scale = pumps_draws$scale,
                                           .chain = pumps_draws$chain, .iteration = pumps_draws$iteration))
posterior::summarise_draws(draws, "mean", "sd", "rhat", "ess_bulk", "ess_tail")

R-hat is 1.001 for the shape and 1.003 for the scale, and every ESS is above 2,000: these draws pass every check from Lesson 8. Because R-hat compares the chains, it needs to know which draw came from which chain. That’s why the .chain column matters.

Your turn. How precisely do 4,000 draws pin down the posterior mean of the shape? Compute its Monte Carlo standard error.

Lesson 8’s function for the MCSE of a mean is posterior::mcse_mean().

posterior::mcse_mean(pumps_draws$shape)

0.006, so the posterior mean is 1.863 ± 0.006, and “1.86” is the right way to report it. The posterior SD is 0.29, about 50 times larger: nearly all the uncertainty is about the pumps, not about the simulation.

brms: models from formulas

Writing Stan programs is the most flexible way to work, but for the common models, brms (Bayesian regression models using Stan) is faster. You write an R formula, choose a family and priors, and brms writes the Stan program, compiles it and samples. Here’s Lesson 7’s flammability model, with the same priors:

library(brms)
flam <- read.csv("data-raw/flammability.csv")
flam$x <- flam$conc_pct - 1.4
fit <- brm(
  ignitions | trials(tests) ~ x, family = binomial(), data = flam,
  prior = c(prior(normal(0, 2.5), class = Intercept),
            prior(normal(0, 25), class = b)),
  seed = 5092
)
summary(fit)

The formula reads “ignitions out of tests trials, depending on x”. The left-hand side’s | trials(tests) is brms’s way of giving the binomial its number of trials, like cbind(ignitions, tests - ignitions) in glm(). Here’s the summary:

#>  Family: binomial 
#>   Links: mu = logit 
#> Formula: ignitions | trials(tests) ~ x 
#>    Data: flam (Number of observations: 5) 
#>   Draws: 4 chains, each with iter = 2000; warmup = 1000; thin = 1;
#>          total post-warmup draws = 4000
#> 
#> Regression Coefficients:
#>           Estimate Est.Error l-95% CI u-95% CI Rhat Bulk_ESS Tail_ESS
#> Intercept    -0.38      0.61    -1.62     0.78 1.00     2223     1812
#> x            11.55      3.82     5.21    20.47 1.00     2525     1634
#> 
#> Draws were sampled using sample(hmc). For each parameter, Bulk_ESS
#> and Tail_ESS are effective sample size measures, and Rhat is the potential
#> scale reduction factor on split chains (at convergence, Rhat = 1).

Read it like a glm() summary, with Bayesian columns: Estimate is the posterior mean, Est.Error the posterior SD, and l-95% CI and u-95% CI the 95% credible interval. Then come the convergence diagnostics, R-hat and the two ESS. The slope, 11.55, and its interval from 5.2 to 20.5 match Lesson 7’s grid. stancode(fit) shows the Stan program brms wrote, about 40 lines. Its main difference from a hand-written one is that it centers the predictors, which helps the sampler.

Your turn. The setup code has brms’s draws in flam_draws, with columns alpha (the intercept) and beta (the slope). Compute the posterior of the LFL50, 1.4 - \alpha/\beta, and compare it with Lesson 7’s 1.43% (1.32% to 1.54%).

Divide by the slope, flam_draws$beta.

lfl50 <- 1.4 - flam_draws$alpha / flam_draws$beta
c(mean = mean(lfl50), quantile(lfl50, c(0.025, 0.975)))

1.434% (1.325% to 1.546%). Lesson 7’s grid, rejection and importance samplers, Lesson 8’s HMC, and now brms: five methods, one posterior.

Your turn. And the safety question: the posterior mean ignition probability at 1.1%, its 95% interval, and the probability that it’s above 5%.

5% is 0.05.

p_low <- plogis(flam_draws$alpha + flam_draws$beta * (1.1 - 1.4))
c(mean = mean(p_low), quantile(p_low, c(0.025, 0.975)), p_over_5pct = mean(p_low > 0.05))

A mean of 4.0% and an interval up to 16.6%, as in Lesson 7, and a 27% probability that the ignition probability at 1.1% is above 5%. That’s a number the process safety team can act on: more than a one-in-four chance that the safe-sounding limit isn’t safe enough.

brms formulas

brms formulas extend R’s usual ones. A few that you’ll meet in the next lessons:

Formula Model
y ~ x linear regression (with family = gaussian(), the default)
y | trials(n) ~ x binomial: y successes out of n
y ~ x + (1 | group) a separate intercept for each group, drawn from a common distribution (Lesson 11)
y ~ x + (x | group) a separate intercept and slope for each group (Lesson 12)
days | cens(censored) ~ 1 censored data, with a variable that’s "right" for censored and "none" otherwise

The terms in parentheses, (1 | group), are the same as in lme4’s lmer() in Module 3.

Your turn. Write the brms formula for Lesson 12’s leak survey: leaks found out of components inspected in each unit, with a separate intercept for each unit and no predictors. Return the formula itself.

The number of trials is the number of components inspected.

leaks | trials(components) ~ 1 + (1 | unit)

A binomial model with one intercept for the whole plant, plus a deviation for each unit. Typing a formula at the console just returns it, without evaluating anything, so you can build formulas without data. With brms installed, brm(that formula, family = binomial(), data = ldar) would fit it.

Challenge round

Challenge 1 · A pump in its first year. A new pump has just been installed. What’s the posterior predictive probability that its seal fails within a year? For each draw of the shape and scale, the probability is the Weibull CDF at 365 days, pweibull(365, shape, scale). Average it over the draws.

Use the scale draws, pumps_draws$scale.

mean(pweibull(365, shape = pumps_draws$shape, scale = pumps_draws$scale))

5.7%. Averaging the probability over the posterior gives the posterior predictive probability directly, with no need to simulate lifetimes. (Simulating one lifetime per draw with rweibull() and counting the ones below 365 would estimate the same number, with more noise.)

Challenge 2 · Stan against Metropolis. Rerun Module 4’s Metropolis sampler for the pumps, and compare the 5%, 50% and 95% quantiles of its shape draws with Stan’s.

The log shape is the first column of the draws.

pumps <- read_csv("data/pump_field.csv", show_col_types = FALSE)
nll <- function(theta) {
  k <- exp(theta[1]); lambda <- exp(theta[2])
  -(sum(pumps$failed * (log(k) - log(lambda) + (k - 1) * log(pumps$days / lambda))) - sum((pumps$days / lambda)^k))
}
log_post <- function(theta) -nll(theta) + dnorm(theta[1], 0, 1, log = TRUE) + dnorm(theta[2], 7.5, 1, log = TRUE)
set.seed(4113)
draws <- matrix(NA, 10000, 2); current <- c(0, 7); lp <- log_post(current)
for (i in 1:10000) {
  proposal <- current + rnorm(2, 0, 0.15); lp_prop <- log_post(proposal)
  if (log(runif(1)) < lp_prop - lp) { current <- proposal; lp <- lp_prop }
  draws[i, ] <- current
}
rbind(stan = quantile(pumps_draws$shape, c(0.05, 0.5, 0.95)),
      metropolis = quantile(exp(draws[-(1:1000), 1]), c(0.05, 0.5, 0.95)))

Stan: 1.40, 1.85 and 2.36. Metropolis: 1.36, 1.86 and 2.39. They agree to within the Metropolis chain’s Monte Carlo error, which is several times larger than Stan’s: its 9,000 draws are worth about 730 independent ones, and Stan’s 4,000 about 2,400. Stan did it with no tuning, and in a fraction of the time.

Quick quiz

1. In a Stan program, where do the priors and the likelihood go?

The model block builds the log-posterior, with ~ statements and target +=.

2. What does target += weibull_lccdf(days[i] | shape, scale) add for a pump that’s still running?

That’s the censored likelihood: all we know is that the pump lasted at least that long.

3. What does Stan do during warmup?

Compilation happens once, before sampling. Warmup adapts the sampler to the posterior.

4. In a brms summary, what is “Est.Error”?

It’s the Bayesian counterpart of a standard error. The Monte Carlo error is much smaller, and depends on the ESS.

5. What does y | trials(n) ~ x mean in brms?

With family = binomial(), it’s logistic regression for counts out of a known total.

6. Why should you compare a new Stan model with an earlier fit of the same model, when you have one?

Bugs in a model’s code are common. Two methods with the same bug are rare.

Wrap-up

You can now read and write Stan programs, and fit models with brms. Here’s what you’ve learned:

  • Stan separates the model from the sampler. A program’s blocks declare the data, the parameters and their transformations, the log-posterior, and quantities to compute from each draw.
  • Censoring takes one line: weibull_lccdf() for the pumps still running. Stan’s posterior for the shape, 1.86 (1.32 to 2.49), matches Module 4’s.
  • cmdstanr compiles and samples from R, with 4 chains of 1,000 warmup and 1,000 kept draws by default, and reports R-hat, the bulk and tail ESS, and the sampler’s diagnostics.
  • brms writes the Stan program from an R formula. The flammability model took one call, and gave the same LFL50, 1.43%, as every method before it.
  • Posterior draws answer the questions: a 93% probability that the pumps’ B10 life is over a year, a 5.7% chance that a new pump fails in its first year, and a 27% chance that 1.1% vapor isn’t safe enough.
TipPractice in RStudio (optional, about two hours, the first time)

Install Stan. This takes about 30 minutes and 2 GB of disk space, once.

  1. On Windows, install Rtools for your version of R, from CRAN’s Rtools page. (On a Mac, install the Xcode command line tools by running xcode-select --install in the Terminal.)

  2. In R, install cmdstanr and brms:

    install.packages("cmdstanr", repos = c("https://stan-dev.r-universe.dev", getOption("repos")))
install.packages("brms")

  3. Install CmdStan itself, Stan’s command-line program, and check it:

    cmdstanr::check_cmdstan_toolchain(fix = TRUE)
cmdstanr::install_cmdstan(cores = 4)

  4. Tell brms to use it: options(brms.backend = "cmdstanr"), in your .Rprofile or at the top of each script.

Then download pump_field.csv, flammability.csv and pumps.stan, and:

  1. Fit the pumps model with the cmdstanr code above. Check that your summary matches this lesson’s. (With the same seed on a different computer, the draws may differ slightly, but the summary should agree within Monte Carlo error.)
  2. Fit the flammability model with brms, and try plot(fit) (trace and density plots), pp_check(fit) and conditional_effects(fit).
  3. Change the prior. Refit the flammability model with prior(normal(0, 5), class = b), a much narrower prior for the slope. How much does the LFL50 change? And the ignition probability at 1.1%?
  4. Read brms’s Stan code with stancode(fit). Find the likelihood, the priors and the centering of the predictor.
NoteKey words from this lesson
Probabilistic programming language
A language for writing statistical models, whose software then does the inference. Stan is the most widely used.
Stan blocks
The sections of a Stan program: data, transformed data, parameters, transformed parameters, model and generated quantities.
No-U-Turn Sampler (NUTS)
Stan’s version of Hamiltonian Monte Carlo, which chooses each trajectory’s length automatically, stopping when it starts to turn back.
Warmup
The first part of each chain, used to tune the step size and the mass matrix, and then discarded.
Automatic differentiation
Computing exact gradients of a program’s output with respect to its inputs, automatically. Stan uses it to get the gradients HMC needs.
cmdstanr
The R interface to CmdStan, Stan’s command-line program.
brms
An R package that fits Bayesian regression models in Stan from R formulas.
Generated quantities
Values computed from each posterior draw after sampling, such as predictions or derived quantities.
