Pruning and tree size

Grow it big, then cut it back

Grow a churn tree until it can’t grow any more, watch it overfit, and cut it back with cost-complexity pruning. Read rpart’s complexity table, choose the size by cross-validation with the minimum rule and the one-standard-error rule, check both choices on the validation accounts, and find out that the answer depends on whether you’re counting mistakes or ranking accounts. Then prune the catalyst-life tree too.

Module 8 · Lesson 5 of 13 Week 123 of 160 About 5–7 hours

How big should a tree be? Lesson 2’s stopping rules (a minimum leaf size, a maximum depth, a minimum improvement) all decide while the tree grows, and they have a known flaw: a split that looks useless can make a very useful split possible further down. The interaction between price and the technical service contract is like that: price alone splits the churn data weakly, but under it, the service contract splits strongly.

CART’s answer, from Breiman and colleagues’ 1984 book, is to grow the tree too big, then prune it back. Pruning removes the branches that add the least, one at a time, which gives a nested sequence of smaller and smaller subtrees. Cross-validation, or a validation set, then picks the best one.

Gardeners know this one: let it grow, then prune what isn’t pulling its weight. It works for trees made of data too!

In this lesson you’ll:

  • grow a tree with no complexity penalty, and watch it overfit
  • read rpart’s complexity table: CP, relative error, cross-validated error
  • prune with the minimum-error rule and the one-standard-error rule
  • check the choices on the validation set, by error rate and by AUC
  • compute the cost-complexity criterion by hand
  • see how much the cross-validated choice depends on the random folds

A tree grown too far

With cp = 0, rpart keeps splitting as long as a split improves the fit at all, until the leaves get too small (by default, a node needs 20 cases to be split, and a leaf needs 7).

The setup code makes Lesson 1’s partition, and defines auc() and a helper, err(), which gives a tree’s misclassification rate on some data.

Your turn. Grow the tree with cp = 0, and compare its training and validation error rates.

No complexity penalty: cp = 0.

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
c(leaves = sum(big$frame$var == "<leaf>"), train_error = err(big, train), valid_error = err(big, valid))

36 leaves, a training error of 11.2% and a validation error of 20.2%. The tree misclassifies almost twice as often on accounts it hasn’t seen, and on the validation set it’s barely better than predicting “no” for everyone (21.5%). The set.seed() is there because rpart cross-validates every tree it grows, with random folds, and the next step uses the results.

Cost-complexity pruning

Write R(T) for a tree’s misclassification rate on the training data and |T| for its number of leaves. Cost-complexity pruning finds, for each penalty \alpha \ge 0, the subtree that minimizes

R_\alpha(T) = R(T) + \alpha |T| .

At \alpha = 0, that’s the full tree. As \alpha grows, extra leaves cost more, and the best subtree shrinks, down to the root alone. Breiman and colleagues showed that the best subtrees for all values of \alpha form a nested sequence, and that it can be found by repeatedly cutting the “weakest link”, the branch with the smallest improvement per leaf removed.

rpart reports the sequence in its complexity table, cptable. Each row is a subtree, with:

  • CP: the penalty at which it becomes optimal, scaled by the root’s error (rpart’s \alpha divided by R(\text{root}));
  • nsplit: its number of splits (leaves minus one);
  • rel error: its training error, relative to the root’s;
  • xerror and xstd: its 10-fold cross-validated error, relative to the root’s, and that estimate’s standard error.

Your turn. Print the big tree’s complexity table, and find the row with the smallest cross-validated error.

The cross-validated error is the "xerror" column.

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
ct <- big$cptable
print(round(ct, 4))
ct[which.min(ct[, "xerror"]), ]

The smallest cross-validated error, 0.802, is at 19 splits (20 leaves), with CP 0.0064. Look at the whole column, though: the training error (rel error) falls steadily from 1 to 0.567, but the cross-validated error falls to about 0.80 by 5 splits, then wanders between 0.80 and 0.82 up to 24 splits, and rises to 0.91 at 35. Every size between 5 and 24 splits is, within its standard error (about 0.042), as good as any other. That’s typical, and it’s what the one-standard-error rule is for.

Here’s the same table as a picture, made with plotcp()’s logic: the cross-validated error against the tree size, with one-standard-error bars, and a dashed line one standard error above the minimum.

ct <- big$cptable
d <- data.frame(leaves = ct[, "nsplit"] + 1, xerror = ct[, "xerror"], xstd = ct[, "xstd"], rel = ct[, "rel error"])
lim <- min(d$xerror) + d$xstd[which.min(d$xerror)]
ggplot(d, aes(leaves)) +
  geom_hline(yintercept = lim, linetype = "dashed", color = "grey50") +
  geom_line(aes(y = rel), color = "grey60") +
  geom_errorbar(aes(ymin = xerror - xstd, ymax = xerror + xstd), width = 0.6, color = "#C2416C") +
  geom_line(aes(y = xerror), color = "#C2416C") + geom_point(aes(y = xerror), color = "#C2416C", size = 1.8) +
  labs(x = "Number of leaves", y = "Error relative to the root") + theme_minimal(base_size = 12)

Two ways to choose

Your turn. Prune the big tree at the CP with the smallest cross-validated error, and find its leaves, validation error and validation AUC.

Prune at best_cp.

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
ct <- big$cptable
best_cp <- ct[which.min(ct[, "xerror"]), "CP"]
t_min <- prune(big, cp = best_cp)
c(leaves = sum(t_min$frame$var == "<leaf>"), valid_error = err(t_min, valid),
  valid_auc = auc(predict(t_min, valid)[, "yes"], valid$churned))

20 leaves, a validation error of 19.6% and a validation AUC of 0.767, the best AUC of any churn tree so far, as good as Lesson 1’s logistic regression. Pruning took away 16 leaves and lost nothing on new accounts.

The one-standard-error rule (Breiman and colleagues’ own recommendation) chooses the smallest tree whose cross-validated error is within one standard error of the minimum: given that the estimates are noisy, prefer the simplest tree that’s statistically as good.

Your turn. Apply the one-standard-error rule, and find the tree’s leaves, validation error and validation AUC.

Add the minimum’s standard error, the "xstd" column.

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
ct <- big$cptable
i <- which.min(ct[, "xerror"])
limit <- ct[i, "xerror"] + ct[i, "xstd"]
j <- which(ct[, "xerror"] <= limit)[1]
t_1se <- prune(big, cp = ct[j, "CP"])
c(leaves = sum(t_1se$frame$var == "<leaf>"), valid_error = err(t_1se, valid),
  valid_auc = auc(predict(t_1se, valid)[, "yes"], valid$churned))

Just 3 leaves (late deliveries, then a volume drop), a validation error of 19.5%, slightly lower than the 20-leaf tree’s, and a validation AUC of only 0.628. Both rules did their job: they chose by misclassification error, which is what xerror measures, and on that measure the two trees are equal. But a 3-leaf tree ranks accounts into only three groups, and Lena needs a ranking. Pruning should be judged by the measure the business will use.

Pruning with the validation set

The complexity table gives every subtree in the sequence, so the validation set can pick one directly, by whatever measure matters.

Your turn. For every CP in the table, prune the big tree and find the subtree’s leaves, validation error and validation AUC.

Prune at the function’s argument, cp.

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
path <- t(sapply(big$cptable[, "CP"], function(cp) {
  sub <- prune(big, cp = cp)
  c(leaves = sum(sub$frame$var == "<leaf>"), valid_error = err(sub, valid),
    valid_auc = auc(predict(sub, valid)[, "yes"], valid$churned))
}))
round(path, 4)

By validation error, the best subtrees have 7 or 12 leaves (18.6%), and everything from 6 to 23 leaves is within a point of them. By AUC, there’s a jump: subtrees with 6 to 14 leaves have about 0.69, and from 20 leaves on about 0.76 to 0.77, with the best at 22 leaves (0.768). The splits between 14 and 20 leaves are small ones, which hardly change any account’s predicted class, but they break up big leaves and so improve the ranking. For a visit list, a tree of about 20 leaves is the right choice.

Your turn. The cost-complexity criterion trades errors against leaves. With R(T) = relative training error × the root’s error rate (388/1,962), compare R_\alpha(T) for the 20-leaf and the 3-leaf subtrees at \alpha = 0.002 and \alpha = 0.005.

The 3-leaf tree pays for 3 leaves.

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
ct <- big$cptable
R <- ct[, "rel error"] * 388 / 1962
leaves <- ct[, "nsplit"] + 1
r20 <- which(leaves == 20); r3 <- which(leaves == 3)
sapply(c(0.002, 0.005), function(a) c(leaves20 = R[r20] + a * 20, leaves3 = R[r3] + a * 3))

At \alpha = 0.002, the 20-leaf tree wins (0.162 against 0.170): its training error of 12.2% is worth its extra 17 leaves. At \alpha = 0.005, the 3-leaf tree wins (0.179 against 0.222). Somewhere between, the preferred subtree switches, and as \alpha rises through the CP values in the table (times 388/1,962), each subtree in turn becomes the best. Cross-validation’s job is to choose \alpha; the training error alone would always choose \alpha = 0 and the biggest tree.

Your turn. The pruned trees are nested: each is the big tree with some branches removed. Check that the 3-leaf tree’s splits are the same as the first splits of the 20-leaf tree, by comparing the variables of the nodes that both trees have.

Look up the same node numbers in the 20-leaf tree: t20$frame[nodes3, "var"].

set.seed(8051)
big <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
ct <- big$cptable
t20 <- prune(big, cp = ct[ct[, "nsplit"] == 19, "CP"])
t3 <- prune(big, cp = ct[ct[, "nsplit"] == 2, "CP"])
nodes3 <- rownames(t3$frame)
identical(as.character(t3$frame[nodes3, "var"])[t3$frame$var != "<leaf>"],
          as.character(t20$frame[nodes3, "var"])[t3$frame$var != "<leaf>"])

TRUE: the 3-leaf tree’s two splits (late deliveries, then the volume change) are exactly the top of the 20-leaf tree. rpart numbers its nodes so that node k’s children are 2k and 2k + 1, which makes the comparison easy. Because the subtrees are nested, choosing a size never means choosing different splits, only how far down to keep them.

NoteGo deeper: the weakest link

For an internal node t with branch T_t below it, collapsing the branch into a leaf changes R_\alpha by R(t) - R(T_t) - \alpha(|T_t| - 1). The branch is worth keeping while \alpha < g(t) = \frac{R(t) - R(T_t)}{|T_t| - 1}: the improvement it buys per extra leaf. Weakest-link pruning repeatedly collapses the node with the smallest g(t); the successive values of g are the CP values in rpart’s table (divided by R(\text{root})), and each collapse gives the next subtree in the sequence. Breiman and colleagues proved that this sequence contains the optimal subtree for every \alpha. Cross-validation then works on \alpha rather than on trees: rpart grows a tree on each fold’s training part, prunes it at each CP, and measures the held-out error. ISLR’s Algorithm 8.1 summarizes it.

Challenge round

Challenge 1 · The folds matter. rpart’s cross-validation uses random folds. Grow the big tree with seeds 1 to 5, and for each, find the number of splits chosen by the minimum rule and by the one-standard-error rule.

Use the function’s argument: set.seed(s).

t(sapply(1:5, function(s) {
  set.seed(s)
  b <- rpart(churned ~ . - sales_rep, data = train, method = "class", cp = 0)
  ct <- b$cptable
  i <- which.min(ct[, "xerror"])
  j <- which(ct[, "xerror"] <= ct[i, "xerror"] + ct[i, "xstd"])[1]
  c(seed = s, min_rule = ct[i, "nsplit"], one_se = ct[j, "nsplit"])
}))

The minimum rule picks 6 splits for four of the seeds and 9 for the fifth, and the one-standard-error rule picks 2 to 6. With seed 8051, they had picked 19 and 2. When the cross-validated error curve is this flat, which size wins is close to a coin toss, which is another reason to look at the whole path, and at the measure you care about, before trusting one number.

Challenge 2 · Pruning the catalyst tree. Grow the catalyst-life regression tree with cp = 0 (after set.seed(8052)), prune it by the minimum rule and by the one-standard-error rule, and compare the test RMSEs of the three trees.

The one-standard-error tree is row j.

cat_life <- read.csv("data/catalyst_life.csv", stringsAsFactors = TRUE)
cat_life$charge <- NULL
set.seed(8022); tr <- sample(600, 400)
ctrain <- cat_life[tr, ]; ctest <- cat_life[-tr, ]
set.seed(8052)
big_c <- rpart(life_days ~ ., data = ctrain, method = "anova", cp = 0)
ct <- big_c$cptable
i <- which.min(ct[, "xerror"])
j <- which(ct[, "xerror"] <= ct[i, "xerror"] + ct[i, "xstd"])[1]
rmse <- function(tree) sqrt(mean((ctest$life_days - predict(tree, ctest))^2))
c(full = rmse(big_c), min_rule = rmse(prune(big_c, cp = ct[i, "CP"])), one_se = rmse(prune(big_c, cp = ct[j, "CP"])),
  leaves_min = ct[i, "nsplit"] + 1, leaves_1se = ct[j, "nsplit"] + 1)

The full tree (32 leaves) has a test RMSE of 79.7 days, the minimum-rule tree (29 leaves) 78.5, and the one-standard-error tree (18 leaves) 82.2. All three beat Lesson 4’s default tree (12 leaves, 85.4): with a strong, structured signal and 400 charges, bigger trees keep finding real detail, and pruning removes little. The one-standard-error tree gives up 4 days of RMSE for a tree about half the size, a trade worth making if the planners want to read it.

Quick quiz

1. Why grow a big tree and prune it, rather than stop early?

Pruning judges whole branches, not single splits.

2. What does xerror in rpart’s complexity table measure?

For regression trees, it’s the cross-validated sum of squares, relative to the root’s.

3. What does the one-standard-error rule choose?

It prefers simplicity when the estimates can’t tell trees apart.

4. The 3-leaf tree had the same validation error as the 20-leaf tree, but a much lower AUC. Why?

Prune by the measure the decision depends on.

5. In R_\alpha(T) = R(T) + \alpha|T|, what happens as \alpha grows?

Each leaf costs \alpha.

6. Running rpart with different seeds chose different tree sizes. Why?

With a flat curve, many sizes are equally good.

Wrap-up

You can now size a tree properly. Here’s what you’ve learned:

  • Grow, then prune: with cp = 0, the churn tree grew 36 leaves and overfitted (11.2% training error, 20.2% validation).
  • Cost-complexity pruning gives a nested sequence of subtrees, one for each range of \alpha; rpart’s complexity table lists them with their cross-validated errors.
  • The minimum rule chose 20 leaves (validation AUC 0.767); the one-standard-error rule chose 3 (equally accurate, but an AUC of 0.628).
  • The validation path showed why: error and ranking disagree. For a visit list, about 20 leaves.
  • The choice is noisy: different folds chose 2 to 19 splits, because the error curve is flat.
  • The catalyst tree kept improving with size: 29 leaves gave a test RMSE of 78.5 days.

NoteKey words from this lesson
Pruning
Removing branches from a fully grown tree to reduce overfitting.
Cost-complexity criterion
R_\alpha(T) = R(T) + \alpha|T|: the training error plus a penalty per leaf.
Complexity parameter (CP)
rpart’s scaled version of \alpha; a split must improve the fit by at least CP (relative to the root) to be kept.
Weakest-link pruning
Repeatedly collapsing the branch with the smallest improvement per leaf, which gives the nested sequence of optimal subtrees.
Cross-validated error (xerror)
The error of each subtree size, estimated by cross-validation, relative to the root’s.
One-standard-error rule
Choosing the smallest tree whose cross-validated error is within one standard error of the minimum.
